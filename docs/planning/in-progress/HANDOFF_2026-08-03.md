**A flake was fixed while taking these numbers, and it is the kind worth knowing about.**
`research-modules-are-reachable` — one of the two standing checks named below — was intermittently
failing at ~5.1 s against vitest's 5 s default, **only in the full-suite run, never in isolation**.
That is the worst shape a structural guard can take: the failure reads as a real orphan, it passes on
re-run, and people learn to re-run past it. Left alone it would have quietly stopped being trusted.

The cost was `hasCaller` running a regex over every source file's entire text once per module —
about 12,000 full-file scans. Now pre-filtered with `String.includes`, which is a *necessary*
condition rather than a heuristic (the pattern contains the basename literally, so a file without
that substring cannot match). **3,856 ms → 860 ms, same answers**, and re-verified by planting an
orphan module and watching the check name it.

Worth recording the attempt that did NOT work, because the reasoning was persuasive: extracting each
file's quoted literals once and matching against those. The pattern is quote-bounded at both ends, so
it looked exactly equivalent. It is not — scanning for quote pairs left-to-right mis-pairs them after
any apostrophe in prose, so one `don't` in a comment hides every literal after it. It reported twelve
wired modules as orphans. Only running it caught that.

**Two standing checks now exist that did not before, and both found things immediately.** If you
change survey code, these are the ones that will stop you:

- `research-modules-are-reachable.test.ts` — every module in the research directories must have a
  non-test caller, or be listed with a reason. `KNOWN_UNREACHABLE` is a standing inventory of the
  dozen modules that were built and never connected.
- `survey-primitives-are-not-duplicated.test.ts` — the vara factor and the closure ratios may not be
  written as literals outside their one home. It found nine files on its first run.

**The shape worth carrying forward** is the last one. *Authored but not wired* is findable with a
caller grep. *Wired but never fed* is not — the caller exists, the modules degrade honestly when
their optional dependency is missing, and the result is a feature that reports truthfully on work it
never did. Both are invisible to a green suite, because a module's own tests cannot tell you whether
anything calls it or what it passes.

Bugs these found, none of which any existing test would have caught:

- **Every due-north call was silently dropped from every rotation** — `if (!parsed)` where `parsed`
  is an azimuth, and due north is 0. A line called exactly `N 0° E` is the signature of an assumed
  basis, i.e. the survey the module exists to rotate.
- **`fitRotation(pts, false)` returns a hardcoded `scale: 1`**, not an observation, so varas walked
  as feet produced huge residuals with nothing naming the cause.
- **The production build broke while every suite stayed green** — worker's ESM `.js` specifiers
  resolve in Node and vitest but not webpack. Third time here. Fixed permanently with
  `resolve.extensionAlias`.

## 6. Two things worth carrying forward

- **A probe can manufacture a dead site.** Marion failed `fetch()` twice and would have been written
  off as unreachable; in a real browser it loads fine — it bounces through
  `?AspxAutoDetectCookieSupport=1`, which Node's fetch does not survive. A county is listed only
  because its portal answered, but that rule is only as good as the instrument doing the asking.
  *"We could not reach it"* is itself a claim.
- **A county can contradict itself.** San Augustine's banner says its index starts 1800, its welcome
  text says 1856, and a real 1838 deed came back. Both claims are recorded and neither resolved; a
  search between them is told the county disagrees with itself rather than handed a confident answer.
